# Controlled production and recovery

Diagnosis protocol and completed-workflow recovery are specified in [DIAGNOSIS_PROTOCOL.md](DIAGNOSIS_PROTOCOL.md). Managed revisions supply a complete diagnosis contract in the API request, validate it before downstream tasks, and use immutable metadata-correction receipts. `control-recover` preserves compatible completed stages across a protocol repair; `control-fork` retains its conservative review-recheck policy.

The controlled profile owns deterministic operations previously assembled by a supervisor: runtime preflight, trusted loading/session records, workflow dependencies, schema/self-review gates, file materialization, per-task and whole-unit checks, bounded revisions, evidence-linked diagnosis and recovery. It does not infer game semantics or certify plugin claims by field presence.

## Entry points and runtime

Use control-plan/control-run/control-status/control-resume with a JSON arcagi-control/v1 configuration naming workflow_spec, runtime_config, distinct existing evidence/rules/blueprint/implementation task roles, seed/cap/timeout, max_revisions (default100), max_elapsed_seconds (default30days), unknown_policy (revise/stop), and optional revision_targets (a nonempty array of distinct existing IDs). These fields are checked before paid calls. The existing workflow must name one existing aggregate_ledger path. Relative paths resolve against their declaring configuration, never the shell working directory.

Runtime arcagi-runtime/v1 declares python, python_sha256, import_roots, dependencies[{name,version,module, optional module_sha256 and inventory_sha256}], sources[{id,path,sha256}], timeout_seconds. Preflight starts that interpreter with -I and explicit roots; it imports declared packages, checks actual versions and origin ownership and hashes declared source materials. Handoff uses the same selected interpreter and strips Python/provider environment overrides. machine-run/handoff and production-run require explicit runtime configuration; lower-level in-memory production functions remain library/testing interfaces, not autonomous controller success claims. Old configs need migration into new files, not mutation under existing request fingerprints.

A worker context loads hash-verified sources and wraps an adapter whose source_object is an instance of a class, a function defined in the loaded module, or the loaded module itself. It records actual adapter reset/step calls and results. Strict replay trace must match the machine session and action count. This proves recorded calls and source-instance linkage; it is not an OS sandbox, a defense against malicious monkeypatching, or a mathematical proof that an arbitrary adapter faithfully represents the original engine. Plugin goal semantics still require appropriate evidence. Worker processes retain ordinary local filesystem permissions, but receive no provider credentials in environment.

## DS feedback loop and unknowns

Normal failures feed a new workflow revision without Luna. Unaffected completed artifacts become hash-pinned local imports; the union of affected stages and descendants regenerates from initial templates, without stale revision prompts or diagnostic inputs. Imported blind evidence retains its blind lane and requires hash-bound prior workflow/spec/output provenance, verified with a deduplicated iterative graph walk (10,000-node defensive limit); it performs no model request. Re-executed blind tasks retain the blind lane and cannot receive source-derived feedback. They may receive DS's own earlier blind-review output and their prior blind artifact, with verified same-lane workflow provenance. These are actual input contents, not references the model is expected to open. Supervisor findings and source-audit notes are not admitted.

A task gate_review=true returns verdict pass/return/unknown and revision_targets, an array of exact allowed dependency IDs. pass requires []; return/unknown requires one or more distinct IDs. The API request includes the effective schema and allowed targets. Nonblind reviews cannot address blind stages. A legacy revision_target is accepted only as an exact valid singleton (or a valid ignored legacy field on pass); prose and delimiter-separated IDs are never guessed or silently redirected. Invalid addressing returns structured protocol facts to the review producer. Fresh, cached and imported reviews use the same gate. A valid returned self-review stops downstream calls and regenerates all addressed stages. It is a DS self-check, not independent semantic acceptance. The controller can also honor a hash-evidenced diagnosis revise_task_id within configured revision_targets, excluding blind stages; invalid diagnosis targets return to the producing diagnosis task. Original data are never edited; changes create new versions.

Diagnosis separates fact, root_cause_status and routing. The next revised artifact must include diagnosis matching supplied actual check IDs/evidence refs/statuses, nonempty candidate causes, excluded causes and missing evidence lists, next_check with a declared operation, and fact_refs. Unconfirmed is allowed; unsupported completed checks are rejected and sent back to DS. Requesting a machine repair in prose does not route anywhere. The controller checks structure/provenance, not semantic truth. Requests for diagnostic execution use the bounded next revision and its declared checks; no arbitrary shell/tool access is exposed.

Unknown search/adapter/worker/plugin outcomes and normal errors stay with DS. Same failures trigger offline input/contract checks, not escalation. Revision/time exhaustion is limited, not a supervisor request. Infrastructure/identity failures use a narrow allowlist; runtime codes claimed by generated plugin code are independently rechecked before escalation. Network/provider failures in the model transport and verified environment/integrity failures can block for a supervisor.

## Evidence and recovery

Each run owns state.json, exclusive OS lock, immutable event files, versioned workflow specs, feedback, model records and execution directories. Actual requests alone use the existing aggregate ledger. Interrupted workflow requests use its existing recovery; reconcile_workflow is an offline bookkeeping operation that constructs no provider and sends no request. Interrupted executions preserve partial directories and restart execution without regenerating model output; completed execution reports recover via persisted intent and verified workflow output hashes. Configuration/core/input baselines and the exact current revision spec cannot drift mid-run.

control-pause --run-dir writes a checkpoint request without acquiring the active controller lock. The controller checks it before tasks, requests and rounds. An already active call can complete and settle before pause; no claim of instant cancellation is made. The paused state resumes only via control-resume. Successful supervisor resolution clears active block fields while preserving the original block and resolution events.

control-fork --config NEW_CONFIG --source-run OLD_RUN --run-dir NEW_RUN --previous-core ARCHIVED_PACKAGE is an explicit offline repair continuation. Stop the old process, reconcile interrupted accounting, preserve its original code, then invoke this operation after approved repairs. It verifies old pinned code against the archive and all non-core inputs in place; game, task semantics, provider, ledger and budgets cannot change. It preserves completed eligible artifacts, reruns review gates and descendants, carries the original start time and revision count, and writes a hash-bound migration receipt. The successor is paused; the predecessor is retired and cannot issue more requests. This is recorded external machine intervention, not an autonomous model iteration. A failed fork may leave a partial successor directory; preserve it and use a fresh destination after diagnosis.

Supervision packets contain event ID, stage, safe code, expected/observed facts, version/hash baseline, performed checks and recovery conditions. control-resume --resolution requires matching block_event_id and nonempty hash-verified evidence_refs; structured JSON check evidence must report status=pass. Runtime/integrity preflight repeats. This is an evidenced operator decision, not automatic certification of a supplied check's semantic truth. New core/config baselines require an explicit checked fork rather than silently mixing versions.

Machine feedback expands safe diagnostic facts (codes, expected/observed checks and source locations) into actual API input, plus bounded native search/replay observations. Paths alone are not treated as readable model inputs; full originals remain hash-bound. Large traces are explicitly truncated by a uniform mechanical policy.

Raw private provider responses, environment values and stdout/stderr are not added to diagnosis packets. Machine-generated observations and action traces are retained as legitimate feedback. Internal detailed audits are not model inputs. Local artifacts are integrity checks, not tamper-proof authenticated storage.

Worker stdout/stderr are opaque captured bytes, not protocol data and not locale-decoded. Only the explicit UTF-8 report file supplies execution verdicts. The deployment launcher reads configuration and writes CLI JSON as UTF-8, independent of Windows locale.

## Completion and tests

Only strict-unit success combines actual per-task structure/search/replay/claim checks, complete blueprint coverage, whole-unit checks and a machine-session-backed reset/step smoke. Missing hooks/proof prevent success. Individual library/legacy engine_only or design_and_engine outputs must not be reported as autonomous full delivery.

examples.neutral_machine.controlled supplies a scripted offline provider and tiny independent reference source. It exercises real WorkflowRunner calls, local frozen imports, worker execution, unknown->diagnosis->revision->pass, infrastructure waits and zero-extra-request recovery. These tests are not a real-game generation or generalization evaluation.
