# Probe 监督与反馈工作协议 v2

## Diagnosis protocol update

The machine supplies the complete versioned diagnosis schema, operation vocabulary, executed checks and evidence references with each managed revision request. Validation runs before dependent tasks. Format corrections use a bounded DS metadata workflow and a hash-bound receipt; the original game artifacts remain available for execution. Compatible completed stages can resume through `control-recover`. See `DIAGNOSIS_PROTOCOL.md` for the interface and recovery procedure.

本协议约束协调者、独立验收 agent 和提交给模型的反馈。适用于后续 probe。main 不得包含任何游戏规则、机制、固定关卡数量或教学顺序特例。

## 职责与输入

DeepSeek 负责从事先声明的合法输入中观察、推断规则、提炼 blueprint、选择规则、构造关卡、实现插件并自行诊断和修订游戏产物。协调者负责运行通用机器、管理文件与预算、检查权限和输入边界、执行检查和归档；不能提供游戏分析、解题线索、机制安排或实现修法。验收 agent 判断是否满足要求，不担任辅助解题者。

合法输入及其可见阶段在调用前固定并记录哈希。轨迹盲分析不得看到源码或源码发现；历史轨迹保持 unbound。重新运行不得以归档旧派生产物、详细审计或协调者分析作为隐含先验。通用 JSON 接口、类型、预算和错误码属于允许的机器说明；游戏语义不属于机器说明。

## 两层验收记录

1. 内部审计报告：可记录可复查的详细反证、轨迹位置和比较结果，供人类审计与归因。标记 internal_audit_only，禁止作为 workflow 输入、依赖、提示词或反馈附件。
2. 模型可见反馈：独立生成最小反馈包，只含验收结论、检查项、受影响的产物自身条目 ID/字段路径、问题类型和已声明要求。不能复制内部审计正文或通过引用它的路径让模型获得细节。

产物条目 ID 用于说明哪一项没有通过，不得新增定位到原始轨迹的步数、坐标、动作片段、源码行号或提示搜索方向的引用。若原产物已经含有相关引用，模型可自行回查；监督者不扩大其定位范围。问题类型限于中性判定，例如 evidence_consistency_failed、unsupported_claim、required_field_missing；不得把具体遗漏内容写进名称。

允许示例：条目 X 未通过 evidence_consistency 检查；请自行依据本阶段原有合法输入复核，返回完整新版本。
禁止示例：第 N 步还改变了某区域；去检查某动作后的状态；这里实际规则是某机制；用某搜索方式或关卡安排修正即可。

完整审计、人工补写的参考答案、具体正确观察、缺失区域、规则解释、代码补丁和推荐关卡方案均不得交给 DeepSeek。反馈不能通过文件名、摘要、错误码、引用或验收 agent 的建议间接泄露这些内容。

## 机器事实与语义提示的区分

机器原生检查结果（schema 字段错误、结构化错误码、搜索状态、原始引擎拒绝、由本次执行产生的动作/轨迹）可按既定接口原样返回，保留产生者和哈希，不由协调者补充因果解释。详细执行轨迹只能来自事先声明的正常运行接口，不能因验收发现而额外制作提示片段。不能借机器诊断包夹带人工发现的游戏语义。

游戏产物类：提交最小反馈及原有合法输入/产物，让模型自行诊断。机器运行类：检查环境、依赖和协议；确认跨游戏通用缺陷后才可改 main，必须中立检查并经新开的 GPT-6 Luna high 独立验收。未定类：保存不确定性和缺失证据，不靠失败次数改判、不先修改游戏或 main。

受控运行中，每次模型调用前由机器核验声明输入、依赖、哈希和 lane，不设置协调者逐次放行关口。独立 GPT-6 Luna high 在最终/机器交付验收中检查边界；人工审计不能成为日常修订顾问。人工无法确定某条反馈是否泄露解法时，不发送该细节。不得为绕开输入限制而将受限内容改标为 general lane；通用 lane 仅表示协议未作盲性认证，不能用来声称 source-blind 已获机器保证。

## 续跑与污染处理

每次调用记录输入哈希、反馈包哈希、运行/请求 ID、模型返回信息、预算和人工介入。事实、归因、内部审计、模型可见反馈分别保存，旧版本不覆盖。模型可见反馈必须列出实际发送的字段，不能只记“已反馈”。协议是操作约束，尚不是自动内容过滤器；不能宣称机器已自动保证所有语义边界。

若越界信息已经发出：记录发送事实，保留费用及请求；将受影响产物和所有读取它的后继运行标记 invalid_for_independent_probe。不能通过删除提示或再次验收把污染结果恢复为独立证据。恢复只能从发送前的合法检查点开一个全新、无被污染上下文的 workflow，不读取污染结果或详细审计，只给原有合法输入、原产物及最小反馈。污染前产物仍是历史待修订产物，不自动作废，也不能因污染版本通过而宣称它已通过。

## 监督记录字段

反馈包至少记录：protocol_version、check_id、artifact_ref/path/hash、item_ids、verdict、failure_type、requirement_ref、allowed_input_refs、internal_audit_forwarded=false。审计与反馈使用不同文件。每个反馈包在调用前记录边界检查结论；不自动重试、不新建预算总账。

独立验收提示必须包含：只判断是否满足要求；详细证据写入 internal_audit_only；另给不含新增轨迹定位、正确内容、语义解释或修法的最小反馈；不得向实现者提供游戏方案。最终报告区分正常产物迭代、机器检修、人工介入、提示污染和未解决问题。


## 模型分工与子 agent 调用门槛（v2，优先适用）

主监督员仅使用 GPT-6 Luna high（工具标识 gpt-6-luna，reasoning_effort=high）。除唯一专职机器检修员外，所有子 agent（含阶段审核、反馈边界检查、独立验收）也只能使用 GPT-6 Luna high。专职机器检修员是唯一允许使用 GPT-6.1 Sol low 的角色（gpt-6.1-sol，reasoning_effort=low），不另设 Sol 总审、规则顾问或通用帮手。模型不可用时不得静默替换，向用户报告。DeepSeek 是 workflow 被测生产模型，不属于上述监督子 agent；仍仅经 workflow 调用。

默认主监督员自行运行和归档，不为每次失败开启子 agent。独立 Luna 验收只在既定阶段产物候选完成、机器补丁交付和最终交付时进行；RETURN 后先由 DeepSeek 完成修订，再复核，不让验收者陪跑解题。不以降低模型调用费用为由跳过已约定的独立验收。

### 不触发机器检修的情况

观察遗漏、证据引用不充分、线索归因错误、规则推断矛盾、blueprint 不合理、关卡职能不落实、生成布局无效、候选路径被引擎拒绝、插件实现错误、模型 JSON 不符合明确协议，均属于被测产物的正常诊断修订范围；由 DeepSeek 自行处理。失败次数多、修得慢、监督者看不懂规则、搜索 unknown，均不是召唤强模型或修改 main 的依据。引擎不一致、导入失败、超时等多因事件继续保留未定，不能仅凭报错名称或次数判作机器缺陷。

### 唯一 Sol 检修员的启动条件

先由主监督员完成已有只读检查：核对调用参数、路径、版本、输入/输出哈希、依赖绑定、既定协议和结构化事件。明确的环境配置问题按文档修复并记录，不因此改 main。未能确认根因，不等于需要 Sol。

只有满足以下任一条件且影响后续合规执行，才允许启动专职 Sol 检修员：

- 已有可复查证据指向跨游戏基础设施：例如中立复现失败、核心接口与已声明契约自相矛盾、预算/续跑/哈希/归档不变量破坏；不能只提交游戏规则错误或插件断言。
- 完成现有检查后，仍有明确的运行层阻断，无法在不改变协议、跳过检查或改动核心的情况下继续。检修包须说明实际阻断、不确定原因、已排除项及为何不能交还 DeepSeek；单纯游戏推断未定不满足此项。
- 发生或即将发生输入隔离、密钥保护、预算完整性或监督信息边界事故，且既定安全默认动作（不发可疑细节、暂停受影响步骤、保留记录）不足以确定合规恢复方案。普通反馈细度拿不准时直接省略细节，不调用 Sol。

已知的简单越界事故可按既定污染隔离流程处理，不必召唤 Sol。启动记录必须有 gate_type、事件/文件哈希、阻断描述、已做检查、请求的机器层问题、允许写入范围、模型配置。无这些证据不得调用；新开无游戏分析历史的检修上下文，优先只给机器契约、日志和中立复现，不提供详细游戏审计。

### 检修员权限与回收

Sol 只诊断环境、协议和跨游戏通用机器问题；不检查游戏线索推导是否正确，不给规则、关卡、搜索策略或插件修法。若证据最终指向游戏产物，返回 artifact_revision 或未定事实并结束，不能转为游戏顾问。需要更多证据时只索取机器层记录或中立复现。

每次启动按一个具体阻断限界；完成即结束，不长期驻留、不按每轮定时唤醒。仅在确认通用代码缺陷后修 main，先写修复依据，以中立测试证明适用其他游戏；新开 Luna high 独立验收通过后，才冻结并同步新基线。检修者不能验收自己的补丁。所有机器修复、环境干预和新基线均记录哈希及人工介入，不能算作机器自主产物迭代。

待诊断时暂停受影响步骤，其他确实独立的步骤可继续。不得以推进整轮为由临时放宽协议或让强模型补答案。最终审计默认 Luna high，不自动升级 Sol。


## 接口信息完整性与低效 revision 防护（2026-11-06）

机器 API 类型、数据结构、错误码及调用签名应完整提供，不属于游戏解题提示；禁止用“最小反馈”隐去模型正确接入机器所需的契约。实现任务必须携带 execution_contract=design-production/v1 及真实 production_api/design_validation_api 文件输入和 sha256，先过 workflow-plan 与 machine-plan。不修改历史 run/spec，只开新版本；标记只是启用检查，不能靠口头声明代替实际文件内容。

若同一接口检查连续两版失败，下一次付费请求前机器先做不调用模型的输入/版本/哈希/接口预检并保存结果。确认基础设施或完整性阻断才交监督员；正常协议错误留在 DS 自修。失败重复不能触发逐版人工审查，也不允许代写游戏产物。

运行前安全检查只阻止有依据的不安全行为及确定的协议不兼容。安全边界通过后，应使用现有执行验证产生结构化事实，不要求静态审阅提前证明完整通关。不存在普适的非空动作要求：初始目标必须由真实绑定引擎确认，不可用 payload 自证。

本防护不构成所有错误的自动阻断：直接调用未标记 workflow 可绕过实施契约门，语义反馈边界和停止低效循环仍需要监督员遵守。失败重复本身不能改归因，不能升级 Sol，更不能放宽验收。


## 系统检修后的运行约束（2026-11-06）

已完成且合法的产物可通过 frozen_output 固定哈希本地导入，不再付费调用模型透传；导入仅证明来源/字节/格式。轨迹盲分析还必须通过同盲 lane 的工作流来源核验，禁止直接导入无来源答案。新模型实现请求继续只经 workflow，携带精确 API 文件；先计划预检，再运行。不得修改历史 spec/run 来迁就新代码。

传输中断（incomplete_response）不是模型输出长度截断，不得仅凭传输错误推断需要增大输出上限。先核对安全结构化网络事实与执行权限，正常网络错误不构成修改 main 的理由。显式 env-file 是 provider 配置权威来源，禁止读取真实配置来人工排查密钥。

语法、类型、schema、worker报告等明确协议错误可先离线发现；安全边界通过的代码进入既有机器验证，而非等待静态审阅证明通关。严格布尔检查防止字符串等误作成功；插件回放、职能声明和源码绑定的真实性仍须独立验收，不能用“字段存在”代替真实性。监督员和验收员仍只能用 Luna high，专职检修Sol low门槛不变。


## 受控运行职责（本节覆盖旧的宽泛未定错误出口）

正常生产与诊断在control-*控制器内部：DS产物、机器执行、真实反馈、DS诊断/修订。Luna不逐版审查、不拼下一版spec/目录。保留“根因未确认”，但它不是交给监督员的路由。DS必须引用真实检查ID、状态和文件哈希，列出候选原因、已检查/排除项、缺证据及下一项检查；不强迫编造确定结论。诊断/修订额度耗尽记limited，不升级Luna。

仅由机器独立确认的基础设施/完整性阻断进入waiting_supervisor。模型自报代码、错误所在插件文件、重复次数和自由文本不足以交接。监督员接收具体事件、检查、事实、版本哈希和恢复要求；恢复必须提交解决证据并重新预检。仅高门槛检修员可用6.1 Sol low；其他监督/验收均Luna high。

交付main和新区时仍由独立Luna high验收。运行中的DS gate_review属于自查，不是独立验收。运行结束的外部审计不可悄悄变成反馈顾问。详见CONTROL_PLANE.md。

## 修订目标与换版续接补充（2026-11-06，优先适用）

DS 自审使用 `revision_targets` 精确 ID 数组，机器在实际请求里声明可选范围。非法字符串、多个 ID 拼成一串、范围外目标均返回明确协议检查给原产出任务；禁止机器猜意图或静默改成重做审查。合法多目标同时修订并使相关下游失效；不受影响的完成产物复用。

DS 自己的同盲 lane 审查意见与先前盲产物可以通过机器核验来源后作为实际内容交回 DS。它们属于 workflow 内部自纠，不是 Luna 提示；源码审计、监督者分析和外部详细审计仍不得回灌盲分析。盲任务的协议纠错提示只含机器产生的协议要求，不含游戏观察。

机器修复换版必须保全旧代码、状态、预算与产物，通过 `control-fork` 建立有来源的新检查点；不能手改旧基线哈希。新检查点保留起始时间和已用修订轮数、沿用唯一账本，复查自审关口。旧运行退役，禁止双区/双进程记账。`control-pause` 在任务/请求边界暂停；已发出的请求可先结束结算。完整接口见 CONTROL_PLANE.md。
